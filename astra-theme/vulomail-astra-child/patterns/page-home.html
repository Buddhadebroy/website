The quiet problem

WordPress email fails without making a sound.

Order confirmations, password resets and form notifications are some of the most important messages your site sends. By default they travel the least reliable route.

Your host 1

Limits or blocks mail

WordPress sends from your web server by default. Many hosts throttle it or switch it off entirely.

Your customer 3

How a message travels

01

Your site sends an email.

WordPress, WooCommerce, your forms, any plugin calling wp_mail(). Nothing in those plugins changes.

02

VuloMail picks it up.

It reads every header shape WordPress accepts, applies your sender, guards against header injection and labels the plugin that sent it.

03

Your primary tries first.

The message goes to the provider you chose. If it is down, rejects the key, or times out, VuloMail doesn't give up.

04

The backup takes over.

Your second connection is tried straight away. If both fail, WordPress's own mailer can still try as a last resort.

05

One entry in the log.

Every attempt is kept on a single row, so you can see exactly what happened. Optionally, a text tells you something failed.

Five rules the code keeps

Built to be boring in all the right ways.

01

Unconfigured means untouched

Activating VuloMail changes nothing. WordPress keeps sending as it always has until you set a primary connection.

02

Adapters never throw, never leak

A provider failure becomes a clean, failed result with credentials scrubbed out of the error text.

03

Secrets never leave the server

Saved keys come back masked. The browser never holds the real value, so it can never send it anywhere.

04

One log row per message

Primary, backup, last resort: every attempt is recorded on a single entry, not scattered across many.

05

Privacy by default

Message bodies aren't stored unless you opt in. Recipients can be masked. Old entries prune themselves.

All questions & troubleshooting

Does activating VuloMail change how my site sends email?

No. Nothing changes until you add a connection and set it as primary. Until then WordPress sends exactly as it did before.

Do I need a VuloLabs account or a paid plan?

No. VuloMail is free, has no Pro edition, and contacts no VuloLabs server. You use email and SMS providers you already have.

Which emails does it cover?

Everything sent with WordPress's standard wp_mail() function: password resets, new-user emails, comment notifications, WooCommerce order emails, contact form notifications and emails from most plugins. A plugin that talks to an email service directly, without wp_mail(), is not affected.

What do I need to run it?

WordPress 6.4 or newer, PHP 7.4 or newer, an administrator account, and an email account: any SMTP server, one of 22 email APIs such as SendGrid, Postmark or Resend, or a one-click preset such as Gmail, Microsoft 365 or Amazon SES. An SMS provider and WooCommerce are optional.

Does “Sent” mean the email was delivered?

It means your provider accepted it. Delivery to the inbox is reported in your provider's own dashboard, and you can look the message up there using the Provider ID in the log entry.
